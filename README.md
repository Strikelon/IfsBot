# IfsBot

Telegram-бот, который помогает человеку разобраться в том, что его беспокоит, через подход IFS (система внутренних семейных систем). Разбирает три вида обращений:

- **сон**;
- **волнующую ситуацию**;
- **внутренний конфликт**.

Человек рассказывает текстом или голосом, бот задаёт уточняющие вопросы, делает разбор и дальше отвечает на вопросы по нему. Бот запоминает важные факты о жизни человека и учитывает их в следующих разборах.

К боту прилагается веб-админка: список подписчиков, статистика по каждому, траты на нейросети, выдача безлимитного доступа.

## Как это устроено

```
Telegram  ──►  бот (сервис dream-bot, порт 8080)  ──►  OpenRouter (разборы)
                    │                              ──►  OpenAI Whisper (голосовые)
                    ▼
               PostgreSQL  ◄──  админка (сервис dream-admin, порт 8081)
```

- **Бот** получает сообщения от Telegram методом long polling, поэтому домен и HTTPS не нужны.
- **Нейросети.** Разборы и вопросы делаются через [OpenRouter](https://openrouter.ai): одним ключом там доступны модели Google, OpenAI и Anthropic. Голосовые распознаются через OpenAI Whisper.
- **База** — PostgreSQL на том же сервере. Всё состояние разговора хранится в ней, поэтому перезапуск бота не теряет, где человек остановился.
- **Админка** слушает только `127.0.0.1` и снаружи недоступна. Открывается через SSH-туннель (см. ниже).
- **Лимиты.** Каждому пользователю считаются траты на нейросети. Когда сумма доходит до лимита, бот показывает сообщение с вашим контактом и предлагает бесплатный доступ за короткое интервью. Выдать доступ можно в админке или командой `/interview` в самом боте.

## Структура проекта

| Папка | Что внутри |
|---|---|
| `src/adapters/telegram/` | Всё, что видит пользователь: обработчики команд и кнопок, **все тексты бота** (`texts.py`), клавиатуры |
| `src/llm/` | Работа с нейросетями: **промпты** (`prompts/`), цепочка запасных моделей (`generator.py`), память о пользователе |
| `src/domain/` | Правила без привязки к Telegram: типы обращений, тарифы и лимиты |
| `src/data/` | Модели базы данных и запросы к ней |
| `src/admin/` | Веб-админка |
| `src/app/` | Запуск бота и все настройки (`config.py`) |
| `alembic/` | Миграции базы данных |
| `deploy/` | Скрипт деплоя, сервисы systemd, бэкап и восстановление базы |
| `scripts/` | Отчёт по аналитике, нагрузочный тест, очистка локальной базы |
| `tests/` | Автотесты |
| `assets/logo.png` | Логотип бота (1024×1024) |

## Что понадобится

1. **Токен бота.** Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot`. Там же можно поставить аватарку из `assets/logo.png`.
2. **Ваш Telegram ID** — число, его покажет [@userinfobot](https://t.me/userinfobot).
3. **Ключ OpenRouter** — [openrouter.ai/keys](https://openrouter.ai/keys), на счёт нужно положить деньги.
4. **Ключ OpenAI** — [platform.openai.com/api-keys](https://platform.openai.com/api-keys), нужен только для голосовых.
5. **Сервер** с Ubuntu 22.04 или 24.04: 2 ГБ памяти, доступ по SSH под `root`.
6. На своём компьютере — **Python 3.12** и **[uv](https://docs.astral.sh/uv/getting-started/installation/)**.

> **Если сервер в России.** Telegram, OpenAI и OpenRouter с российских серверов не работают. Нужен HTTP-прокси за рубежом: его адрес указывается в `LLM_PROXY`, и через него бот ходит ко всем трём сервисам. Если сервер за рубежом, прокси не нужен.

## Настройки

Все настройки лежат в файле `.env` в корне проекта. Скопируйте образец и заполните:

```bash
cp .env.example .env
```

Каждая строка в `.env.example` подписана. Обязательные:
- `BOT_TOKEN`, `ADMIN_ID`, `SUPPORT_CONTACT_URL`;
- `OPENAI_API_KEY`, `OPENROUTER_API_KEY`;
- `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET`;
- для деплоя ещё `SERVER_IP`, `DB_PASSWORD` и ключ или пароль от сервера.

Хэш пароля админки и секрет сессии делаются командами, которые записаны в `.env.example` прямо над этими строками.

`.env` содержит ключи и пароли. В git он не попадает (это задано в `.gitignore`), никому его не пересылайте.

## Деплой на сервер

С вашего компьютера, из папки проекта:

```bash
uv sync
uv run python deploy/deploy.py
```

Скрипт сам подключится к серверу и сделает всё по порядку:
1. Поставит PostgreSQL и uv.
2. Создаст системного пользователя `dream-bot` и папку `/opt/dream-bot`.
3. Создаст базу и зальёт туда код.
4. Запишет на сервер `.env` из ваших настроек.
5. Установит зависимости и создаст таблицы.
6. Включит два сервиса systemd (`dream-bot` и `dream-admin`) и ежедневный бэкап базы.
7. Перезапустит сервисы.

В конце скрипт покажет статус обоих сервисов: должно быть `active (running)`. Напишите боту `/start` и проверьте, что он отвечает.

**Повторный деплой** после любых изменений — та же команда. Скрипт можно запускать сколько угодно раз. Папки с кодом на сервере он каждый раз заливает заново, а базу, `.env` и бэкапы не трогает.

> Перезапуск при деплое обрывает разбор, который бот в этот момент готовит: человек увидит, что ответа нет. Деплойте, когда в боте никого нет. Проверить можно командой `journalctl -u dream-bot --since "-10 min"` на сервере.

## Админка

Админка открыта только внутри сервера. Чтобы зайти, пробросьте порт через SSH:

```bash
ssh -L 8081:127.0.0.1:8081 root@IP_СЕРВЕРА
```

Пока это окно открыто, админка работает в браузере по адресу [http://127.0.0.1:8081](http://127.0.0.1:8081). Логин — `ADMIN_USERNAME`, пароль — тот, из которого вы делали `ADMIN_PASSWORD_HASH`.

Что в ней есть:
- **Подписчики** — таблица с поиском и сортировкой. По каждому: сколько обращений и вопросов каждого типа, траты на нейросети, видел ли сообщение о лимите, был ли на интервью, когда заходил последний раз.
- **Карточка пользователя** — те же цифры, текущий тариф и лимит.
  - Кнопка «Интервью» даёт безлимит на 2 месяца и сама пишет человеку, что доступ открыт. «Обычный тестер» возвращает прежний тариф.
  - «Удалить пользователя» стирает его вместе со всеми данными.

Тексты обращений и разборов админка не показывает.

**Команда `/interview` в боте** делает то же, что кнопка «Интервью», но с телефона. Работает только у владельца (`ADMIN_ID`): `/interview Мария`, `/interview @ник` или `/interview 123456789`.

## Обслуживание

Все команды ниже выполняются на сервере.

| Задача | Команда |
|---|---|
| Логи бота в реальном времени | `journalctl -u dream-bot -f` |
| Логи админки | `journalctl -u dream-admin -f` |
| Перезапуск | `systemctl restart dream-bot dream-admin` |
| Статус | `systemctl status dream-bot dream-admin` |
| Список бэкапов | `ls /opt/dream-bot/backups/` |
| Восстановить базу из бэкапа | `/opt/dream-bot/deploy/restore_db.sh /opt/dream-bot/backups/dream_bot_ГГГГ-ММ-ДД.sql.gz` |

**Бэкап** делается каждый день в 04:00, хранится 7 дней. Бэкапы лежат на том же сервере: если сервер пропадёт, пропадут и они. Время от времени копируйте свежий файл к себе:

```bash
scp root@IP_СЕРВЕРА:/opt/dream-bot/backups/dream_bot_ГГГГ-ММ-ДД.sql.gz .
```

**Оповещение о тратах.** Если за сутки траты всех пользователей превысят `DAILY_SPEND_ALERT_USD`, бот напишет вам в Telegram. Бот при этом продолжает работать.

**Отчёт по аналитике** — воронка знакомства с ботом и возвращаемость по неделям. Запускается с вашего компьютера, по SSH читает базу на сервере и ничего в ней не меняет:

```bash
uv run python scripts/analytics_report.py --cohort week
```

Таблицы и графики появятся в папке `analytics_out/`.

## Что где менять

| Хочу поменять | Где |
|---|---|
| Любой текст, который видит пользователь | `src/adapters/telegram/texts.py` |
| Как бот разбирает сон, ситуацию, конфликт | `src/llm/prompts/quick.py`, `situation.py`, `conflict.py` |
| Вопросы перед разбором | `src/llm/prompts/entry_prompts.py`, `image_questions.py` |
| Модели для разбора и запасные модели | `src/llm/generator.py` (`_QUICK_FALLBACK_CHAIN`) |
| Модели для служебных задач | `.env`: `OPENROUTER_CLASSIFIER_MODEL`, `OPENROUTER_INTENT_MODEL`, `OPENROUTER_CONTEXT_MODEL` |
| Лимиты трат | `.env`: `USER_SPEND_LIMIT_USD`, `NEW_USER_SPEND_LIMIT_USD` |
| Срок бесплатного доступа за интервью | `src/domain/access.py` (`INTERVIEW_MONTHS`) |
| Цены моделей для подсчёта трат | `src/llm/pricing.py` |

Поменяли `.env` — запустите деплой ещё раз, иначе сервер не увидит изменений.

## Запуск на своём компьютере

Нужен для того, чтобы проверить изменения, не трогая настоящего бота. Порядок такой:
1. Заведите у @BotFather второго, тестового бота и укажите его токен в `BOT_DEV_TOKEN`.
2. Поставьте [PostgreSQL](https://www.postgresql.org/download/) и создайте базу:
   ```sql
   CREATE ROLE dream_bot LOGIN PASSWORD 'password';
   CREATE DATABASE dream_bot OWNER dream_bot;
   ```
3. Проверьте, что `DATABASE_URL` в `.env` указывает на эту базу.
4. Выполните:
   ```bash
   uv sync
   uv run alembic upgrade head
   uv run uvicorn app.main:app --app-dir src --port 8080      # бот
   uv run uvicorn admin.main:app --app-dir src --port 8081    # админка, во втором окне
   ```

Пока задан `BOT_DEV_TOKEN`, и бот, и админка работают с тестовым ботом. Настоящий бот при этом не затрагивается. Начать знакомство с ботом заново поможет `uv run python scripts/wipe_dev_db.py`: он очищает только локальную базу.

## Важно о данных

Бот хранит у себя тексты снов, ситуаций и всё, что человек о себе рассказал. Это чувствительные персональные данные, а вы как владелец бота отвечаете за их хранение. Если пользователи — граждане России, закон 152-ФЗ требует хранить их данные на сервере в России и уведомить Роскомнадзор об обработке персональных данных.
